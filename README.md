# Ветки в работе

**https://newyurk.github.io/branches/** — все ветки игр, которые сейчас в работе, собранные так же,
как собирается их `main`. Ссылок на сами игры из `main` на странице нарочно нет — только ветки. Основные адреса (`newyurk.github.io/temari/`, `/rollery/`, `/roti-stand/`) не меняются и по-прежнему отдают `main`: этот репозиторий выкладывает только себя.

Превью ветки живёт по адресу `newyurk.github.io/branches/<игра>/<ветка>/`, например
`/branches/roti-stand/codex/roti-continuation/prototype/dough-closeup/`. Если в имени ветки есть
символы кроме латиницы, цифр и `._-`, они заменяются на `-`, а к этой части добавляется `~` и кусок
хеша имени (`фича/тест` → `----~a670b4/----`), чтобы две ветки не попали в одну папку.

## Как это работает

Главный путь — **push в игре**. В `main` каждой игры лежит `.github/workflows/branch-preview.yml`: после
push или удаления ветки он запускает здесь `publish.yml` (секрет `BRANCHES_DISPATCH_TOKEN` в игре —
fine-grained токен только на `newYurk/branches` с правом Actions: read and write). Превью появляется
примерно через 2 минуты. GitHub берёт этот workflow из самой ветки, поэтому ветки, отведённые от `main`
раньше 17.09.2026, начнут так работать после слияния со свежим `main`. Без секрета или с протухшим
токеном workflow остаётся зелёным (только предупреждение) — остаются запасные пути ниже.

Запасной путь — два workflow здесь:

- `watch.yml` — раз в пять минут (расписание GitHub запаздывает, бывает и на 10–15 минут)
  `node tools/plan.mjs heads` снимает головы всех веток (`git ls-remote`) и открытые PR и хеширует их
  вместе с кодом сборщика. Если ровно это состояние уже выложено (метка `published-<отпечаток>` в кэше
  Actions), на этом всё; иначе запускает `publish.yml`.
- `publish.yml` — собирает и выкладывает весь сайт, потом ждёт, пока `newyurk.github.io/branches/plan.json`
  начнёт отдавать номер именно этого запуска, и только тогда ставит метку. Не дождался — запуск красный,
  метки нет, следующий `watch` попробует снова. Если какая-то ветка не собралась, метка сначала ставится
  «пробная»: следующий `watch` пересоберёт ещё раз (сетевой сбой лечится сам), а после второй неудачи
  состояние считается выложенным, пока что-нибудь не сдвинется.

Почему два файла. Повторные деплои с одним и тем же коммитом из расписания замечены «успешными» без
обновления сайта (actions/deploy-pages#383), а запуски через dispatch сайт обновляют. И ещё: в публичном
репозитории GitHub выключает workflow с расписанием после 60 дней без активности — целиком. Поэтому
`watch.yml` сам делает пустой коммит, если здесь 45 дней не было коммитов, `publish.yml` включает
`watch.yml` обратно, если тот всё же выключен, а страница-список пишет «похоже, автопроверка стоит»,
если push на GitHub старше 20 минут, а превью его ещё не показывает.

Что делает `publish.yml`:

1. `tools/plan.mjs full` — список веток с последним коммитом, отставанием от `main`, PR и пометкой,
   меняет ли ветка что-то в игре или только доки (`quiet` в `projects.json`). Превью всегда собирается
   из головы ветки, поэтому ветка, отставшая от `main`, честно помечена «игра в превью старее».
   Недоступный репозиторий или ветка без общей истории с `main` не мешают остальным.
2. `tools/build.mjs` — каждую ветку по рецепту из `projects.json`:
   - `copy` — то, что отдал бы старый Pages: все файлы, кроме начинающихся на `.` и `_`
     (Ролльня, Роти; Jekyll-рендер `.md` не повторяется — ни одна игровая страница на него не ссылается);
   - `install` / `gate` / `run` / `out` — сборка (Темари: Node 24, `npm ci`, `npm run build`, `dist/`).
     `gate` — те же проверки, что стоят перед выкладкой `main`; если они падают или не укладываются
     в 10 минут, превью всё равно собирается, а в списке появляется красная пометка. Результат
     запоминается по коммиту (кэш Actions `gates-*`): тесты Темари идут минуты, и push в другую игру
     не должен гонять их заново.
3. `tools/inject.mjs` — в каждую страницу превью первым скриптом вставляется:
   - **отдельные сохранения.** Все игры живут на одном домене `newyurk.github.io` и делят `localStorage`.
     Превью пишет под префиксом `branch:<игра>/<ветка>:` и никогда не трогает сохранения `main`
     (ни через `setItem`/`removeItem`/`clear`, ни через `localStorage.x = …`), а читает с откатом на них —
     то есть стартует с твоего настоящего прогресса, как после слияния;
   - **без счётчиков.** Запросы на хосты из `blockHosts` в `projects.json` из превью не уходят
     (сейчас список пуст: счётчик hits.sh был только у «Лягушки», её на странице нет);
   - **ярлык** `⎇ ветка · коммит` сверху и `⎇` в заголовке вкладки. Pages разрешает браузеру держать
     страницу до 10 минут; если ветка с тех пор ушла вперёд, ярлык краснеет — «есть версия новее,
     нажмите, чтобы обновить» (перезагрузка с новым `?fresh=`, игра сама не перезагружается);
   - ссылки на живой адрес своей игры и на её файлы в `blob/main` переписываются на ветку.
4. `tools/assemble.mjs` — страница-список. В браузере она сама сверяется с GitHub и пишет
   «есть новые коммиты — превью догонит», если сборка отстала, и подчищает сохранения удалённых веток.
   Если браузер показал старую копию списка, а на сервере уже новая сборка, список один раз
   перезагружается сам (`?v=<номер запуска>`).

Сломанная сборка одной ветки не мешает остальным: ветка остаётся в списке со ссылкой на лог.

## Что здесь не видно

- **Незапушенные ветки.** Страница знает только то, что есть на GitHub.
- **Изменения в собственной сборке игры** (например, в `temari/.github/workflows/pages.yml`) — рецепт
  берётся из `projects.json` здесь; поменялся у игры — поправить и тут.

## Руками

- Токен протух: создать новый (fine-grained, только `newYurk/branches`, Actions: read and write) и
  положить в три игры:
  `read -rs "T?Токен: " && for r in temari rollery roti-stand; do printf %s "$T" | gh secret set BRANCHES_DISPATCH_TOKEN -R newYurk/$r; done; unset T`
- Новая игра: скопировать `branch-preview.yml` в её `main` и положить тот же секрет.
- Обновить сейчас: Actions → publish → Run workflow (галочка «пересобрать» — даже без изменений).
  Это же возвращает к жизни `watch.yml`, если GitHub его выключил.
- Добавить игру: запись в `projects.json` (`repo`, `title`, `tagline`, `build`, `entries`, `quiet`).
- Проверить локально:

  ```bash
  node tools/plan.mjs full && node tools/build.mjs plan.json _site/branches status.json && node tools/assemble.mjs plan.json _site/branches status.json
  ```

  и открыть `http://127.0.0.1:8761/branches/` после
  `cd _site && python3 -c "import http.server as h; h.SimpleHTTPRequestHandler.extensions_map['.html']='text/html; charset=utf-8'; h.test(h.SimpleHTTPRequestHandler, port=8761, bind='127.0.0.1')"`
  (обычный `python3 -m http.server` не пишет кодировку, и обзор Роти показывает кракозябры; GitHub Pages пишет).
